## Supported operation boundary

AI Work is a single-owner opt-in runtime. Budgeted requests cover supported text
API inference. Provider-resolved inputs and unbounded modalities fail before
dispatch. Native subscriptions and calls outside the gateway remain outside caps.
Provider timing measures transport blocking time, not GPU compute. Workflow
completion establishes its specified condition, not universal correctness.

Automatic signed connectors and integrated full-state recovery are available in
the full SQLite single-node gateway profile with enrolled sources. The fixed
PostgreSQL provider-pilot profile excludes portfolio connectors, supports explicit
workflow checks and requires independently qualified PostgreSQL recovery. Its
dormant SQLite usage file is not a backup of live PostgreSQL state.

Provider account observations come from the existing trusted finance collection
owner, with exact tenant/account bindings and audited read authority. They stay
separate from job estimates and do not certify a final invoice. No customer file
or browser-submitted amount is promoted to provider-confirmed evidence.

## Live gates

Source and local evidence are an implementation candidate. Completing the paid
launch requires a named authorized deployment, real provider/account access,
approved Stripe price and current signed live events, production identity/TLS,
inquiry inbox and booking verification, exact Pages publication, and the signed
release/update path. No suitable live setup has been supplied in this goal turn.

Do not resume paid infrastructure before verified customer payment. No real
inquiry, booking, charge, ad or outreach is generated merely to close a test.
Read [AI_WORK_OPERATIONS.md](AI_WORK_OPERATIONS.md) for concrete activation,
backup/restore, update, removal and support commands.
