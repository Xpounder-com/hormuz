# Hormuz v1.7.0: Native Mac relay integration; Windows preview

Hormuz v1.7.0 is a compatible core/source minor release. It preserves the stable
v1 CLI, policy/evidence contracts, Personal Optimizer, adapter SDK and Aider
integration. Storage schemas and existing provider accounting are unchanged.

## Included improvements

- Development Mac launchers use the existing Rust relay, with authenticated
  loopback access, bounded streaming, invocation-only client settings and no
  automatic replay after an uncertain upstream outcome.
- The Mac executable remains the Keychain credential broker. The launch profile
  travels over a bounded anonymous pipe and is checked under the existing
  session lock; a replacement profile cannot supply credentials to an old relay.
- An app-owned lifetime connection is independent of panels. App exit closes it
  and stops the direct client, relay and cancellable optimizer work. Previously
  saved launchers are rebound after a restored session is gateway-verified.
- The packaged optimizer exposes its existing byte-stream bridge. On-demand
  helpers initialize verified tokenizers before candidate evaluation, retaining
  the candidate-work guard and the native caller's whole-helper timeout. Cold
  startup is additional overhead, not a 100 ms end-to-end latency promise.
- Mac helper cleanup also stops ordinary same-process-group descendants after
  success, failure or cancellation. The release-shaped archive includes the
  Rust relay with architecture, signature/team and digest verification. New
  distribution proofs use schema v4; historical v2/v3 pilot proofs remain valid.

The package tests exercise pinned Codex `0.147.0` and Claude Code `2.1.233`
against local scripted gateways, including actual Codex tool-output compaction,
lossless restoration, streamed Claude responses, Off bytes, bad authentication,
helper failure and owner-exit cancellation. These are provider-free checks, not
live-account, billing-savings or clean-machine acceptance claims.

## Install and verify

```sh
python -m pip install 'hormuz[client,context] @ https://github.com/Xpounder-com/hormuz/releases/download/v1.7.0/hormuz-1.7.0-py3-none-any.whl'
hormuz context resources install
hormuz personal contract --json
hormuz personal qualify --json
```

The wheel/source archives use the core release identity. Verify published
artifacts against `SHA256SUMS.txt`; checksums are not individual package
signatures. Signed Linux AMD64 image evidence, when published, is recorded on
the release page; follow [OCI signature verification](../OCI.md).

## Platform boundaries

**Windows remains an unsigned, unsupported development preview.** Its Rust
package stays `1.5.0-dev.1`. No signed Windows installer is published.

This release does not complete the native Rust launch/relay milestone in
[#341](https://github.com/Xpounder-com/hormuz/issues/341). Mac client-descendant
containment, abrupt relay-death cleanup, interactive panel-close/quit/update
qualification and the remaining platform integrations are still open. Ordinary
helper process groups do not contain deliberately detached `setsid`/`setpgid`
processes. The Rust optimizer port in #342 is also separate, not completed by
reusing the Python optimizer.

The latest Developer ID signed and notarized Mac download remains
[v1.3.0 for Apple Silicon on macOS 14+](https://github.com/Xpounder-com/hormuz/releases/download/v1.3.0/Hormuz-1.3.0-notarized.zip).
No v1.7 Mac app is submitted to Apple or published here. The new Mac behavior
is development source with local ad-hoc archive verification, not a new customer
Mac distribution. Native Linux qualification remains separate from Linux AMD64
OCI support. No hosted deployment, Apple submission, customer acceptance or
general production certification is activated by this core/source release.
