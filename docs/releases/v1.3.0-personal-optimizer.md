# Hormuz v1.3.0: Personal Optimizer

Hormuz v1.3.0 adds a terminal-first Personal Optimizer while preserving the
v1 CLI and policy/evidence contracts.

One developer can connect a supported coding agent directly to an existing
provider account without creating an organization or running PostgreSQL.
Hormuz keeps the provider credential in the operating-system keyring, launches
the agent through an authenticated loopback relay, applies only qualified
lossless local transforms, and records bounded content-free measurements.

The initial component contract is Personal Optimizer 0.1.0 on Apple Silicon,
macOS 14 or later. Codex 0.148.0 is the initial pinned agent. The release also
includes the adapter SDK and an Aider 0.86.2 integration. Run the provider-free
contract checks with:

```sh
python -m pip install 'hormuz[client,context]'
hormuz context resources install
hormuz personal contract --json
hormuz personal qualify --json
```

The benefit view reports exact traffic bytes, local token estimates, provider
usage fields when supplied, latency, overhead, sessions, and exceptions.
Missing observations stay missing. Cost is shown only when a provider returns
an unambiguous actual amount. `personal off` restores the ordinary byte path,
and `personal remove` removes the integration without editing the coding
agent's persistent configuration.

This release does not claim a provider bill reduction, live-model quality,
customer acceptance, willingness to pay, production certification, or
completion of the separate portfolio and native roadmaps. Those are evidence
and roadmap boundaries, not installation requirements.
