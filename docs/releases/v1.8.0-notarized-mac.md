# Hormuz v1.8.0: Notarized Mac companion; Windows preview

Hormuz v1.8.0 is a compatible core/source and Apple Silicon Mac release. It
preserves the stable CLI, policy/evidence contracts, Personal Optimizer,
adapter SDK and Aider integration. Storage schemas and provider accounting
are unchanged. The optional optimizer remains the existing Python helper,
started only on demand; this does not complete the Rust optimizer port in #342.

## Included improvements

- The Developer ID signed and notarized Mac archive includes the Rust relay,
  signed standalone context helper and digest-verified tokenizer resources.
  No separate Python installation is needed for the team companion.
- App-owner exit interrupts both a stalled startup credential exchange and
  client-version discovery. Existing bounded pipes and owned-child cleanup
  stop and reap the helper/probe, returning 130 before client launch,
  optimization or gateway egress. Invalid credentials and unsupported client
  versions still fail closed with status 1 while the owner is present.
- Existing invocation-only client settings, direct-provider environment
  cleanup, loopback authentication, bounded streaming, profile binding and
  uncertain-outcome/no-automatic-replay behavior remain in place.

Package verification uses pinned Codex `0.147.0` and Claude Code `2.1.233`
against synthetic loopback gateways. Those checks do not establish live-account,
clean-machine, buyer benefit, billing savings or production certification.

## Install and verify

Download the [Mac archive](https://github.com/Xpounder-com/hormuz/releases/download/v1.8.0/Hormuz-1.8.0-notarized.zip)
and compare its SHA-256 with the release's
[checksum manifest](https://github.com/Xpounder-com/hormuz/releases/download/v1.8.0/SHA256SUMS.txt).
Keep normal Gatekeeper checks enabled. The app supports Apple Silicon (`arm64`)
on macOS 14 or later; Intel Macs are unsupported. It connects to an existing
team gateway and does not provision a hosted account. Direct Personal Optimizer
use remains the documented terminal setup.

Core installation:

```sh
python -m pip install 'hormuz[client,context] @ https://github.com/Xpounder-com/hormuz/releases/download/v1.8.0/hormuz-1.8.0-py3-none-any.whl'
hormuz context resources install
hormuz personal qualify --json
```

The [release page](https://github.com/Xpounder-com/hormuz/releases/tag/v1.8.0)
records the accepted source, exact-main checks, original CI archives,
notarization receipt, Mac verification, signed Linux AMD64 OCI evidence and
failure/retry history. Core archives are checksum-verified, not individually
signed. OCI support is separate from native Linux desktop qualification.

## Upgrade and remaining boundaries

Quit the old app before replacing it with the versioned archive. Keep the old
archive for rollback. This release does not add an automatic updater, migrate
settings, replace your installed app automatically or certify interactive
upgrade/rollback behavior. The bundle identifier and signing team are unchanged.

**Windows remains an unsigned, unsupported development preview**, package
`1.5.0-dev.1`. No signed Windows installer is published.

This release does not complete the native Rust launch/relay milestone in
[#341](https://github.com/Xpounder-com/hormuz/issues/341). Request-time credential
lookups retain their separate 30-second bound. Deliberately detached client/helper
descendants, abrupt relay-death containment, interactive panel-close/quit/update
acceptance and remaining installed-platform qualification are still open.
The GTK4 Linux companion and full all-platform distribution remain separate work.
No paid-provider qualification, hosted rollout or general production certification
is implied by publishing these verified packages.
