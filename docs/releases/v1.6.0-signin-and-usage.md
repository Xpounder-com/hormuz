# Hormuz v1.6.0: Sign-in and usage improvements; Windows preview

Hormuz v1.6.0 is a compatible core minor release. It preserves the stable v1
CLI and policy/evidence contracts, Personal Optimizer, adapter SDK and Aider
integration. The Python package and signed Linux AMD64 image share one release
identity. Existing SQLite and PostgreSQL storage schemas are unchanged.

## Included improvements

- Normal browser sign-in sets the temporary HTTP-only callback cookie and
  redirects directly to the configured identity provider, without an invitation
  prompt. Approved team membership is still required; verified identity alone
  does not grant gateway access.
- Team invitations use a separate `/v1/auth/join` page. The CLI opts in with
  `hormuz login --join-team`; development Mac clients expose a separate
  **Use team invitation** action. Disabled onboarding rejects join requests
  before creating enrollment, opening the browser or polling.
- Hosted development Mac clients use the server-selected client/model profile
  and handle failed enrollment without saving credentials. The Python launcher
  accepts validated desktop-managed profile metadata while rejecting unknown
  fields and invalid profile versions.
- PostgreSQL secret totals keep their integer wire contract. Aggregated numeric
  values are serialized safely, including an empty usage ledger.
- Both container profiles pin Debian's PCRE2 and Perl security updates with
  verified checksums. Signed provenance binds both patches; the existing
  reproducibility and fixable HIGH/CRITICAL vulnerability gates remain required.

The implementation changes are PRs [#445](https://github.com/Xpounder-com/hormuz/pull/445)
and [#447](https://github.com/Xpounder-com/hormuz/pull/447).
[PR #446](https://github.com/Xpounder-com/hormuz/pull/446) records the earlier
internal Mac sign-in pilot, not a newly published signed Mac application.

## Install and verify

```sh
python -m pip install 'PyJWT[crypto]>=2.14,<3' 'hormuz[client,context] @ https://github.com/Xpounder-com/hormuz/releases/download/v1.6.0/hormuz-1.6.0-py3-none-any.whl'
hormuz context resources install
hormuz personal contract --json
hormuz personal qualify --json
hormuz login --help
```

The explicit PyJWT requirement upgrades older compatible installations; the
signed OCI image pins PyJWT 2.15.1. `SHA256SUMS.txt` binds the wheel, source
archive and content-free OCI evidence. The package archives are checksum-
verified, not individually signed. Pin the Linux AMD64 image digest from
`oci-release-summary.json` and follow [signature verification](../OCI.md).

## Platform boundaries

**Windows remains an unsigned, unsupported development preview.** Its Rust
package stays `1.5.0-dev.1`. No signed Windows installer is published.
Real authorized sign-in, scoped usage, physical desktop interaction,
Credential Manager denial, clean-machine installation and connected footprint
remain open in [#331](https://github.com/Xpounder-com/hormuz/issues/331) and
#337–#340. This core release does not complete the native Rust launch/relay milestone
in [#341](https://github.com/Xpounder-com/hormuz/issues/341).

The latest Developer ID signed and notarized Mac archive remains
[v1.3.0 for Apple Silicon on macOS 14+](https://github.com/Xpounder-com/hormuz/releases/download/v1.3.0/Hormuz-1.3.0-notarized.zip).
No v1.6 Mac app is submitted to Apple or published here. New Mac UI behavior
is development source and internal-pilot evidence, not that older signed archive.
Linux OCI support remains `linux/amd64`; native Linux and ARM64 qualification
continue separately.

The core release does not by itself activate a hosted deployment or claim
live-provider savings, customer acceptance or general production certification.
Exact commits, CI runs, package hashes and signed image evidence are recorded
on the [v1.6.0 release](https://github.com/Xpounder-com/hormuz/releases/tag/v1.6.0).
