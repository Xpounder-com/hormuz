# Small ways to help Hormuz

Start in [Discussions](https://github.com/Xpounder-com/hormuz/discussions/211)
and check [CONTRIBUTING.md](../CONTRIBUTING.md). These are scoped starter ideas,
not claims that someone is assigned or that a test already passed. Coordinate
before opening a PR so work is not duplicated.

| Starter | Acceptance criteria | Out of scope |
| --- | --- | --- |
| Document a first-run troubleshooting case | Reproduce one failure with synthetic inputs; name OS/Python/version; provide a minimal corrective step and expected result; link the existing quickstart | Secrets, customer logs, security-control changes |
| Verify the PowerShell activation path | Try the tagged-source demo in an isolated Windows environment; record the exact environment and commands; report what passed and what did not | Claiming untested production Windows support |
| Review recorded-demo accessibility | Check keyboard play/pause, range control, readable transcript, reduced motion, and zoom; provide concrete reproduction steps for any issue | Invented conformance badges or a full accessibility certification |

Bug reports should be small and reproducible. Use public issue forms only for
non-sensitive material. Suspected vulnerabilities follow [SECURITY.md](../SECURITY.md).
Community support is best effort; no response SLA is implied.
