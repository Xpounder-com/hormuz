HORMUZ: A WORKDAY WITH A $1M AI BUDGET

This is a fictional company, not a customer case study.

1. SPEND AND TOKENS
At day 15 of a 30-day month, $50,000 estimated cost sits against an $83,333.33 budget. The $100,000 monthly pace is a straight-line estimate. Engineering uses 3.9B tokens and $30,000: uncached input $12,600, cached input $900, output $16,500. Output is 12.82% of tokens but 55% of cost.

2. SET A POLICY
Compare Standard (16,000 output tokens, redact configured secrets), Strict (4,000, deny configured secrets), or Lockdown (deny all). With $0.50 available, a $0.70 reservation is denied with zero provider calls. The lower output cap changes that example reservation to $0.22. The maximum output charge falls from $0.64 to $0.16; this is not measured savings. Historical spend does not change.

3. COMPACT CONTEXT
The actual setting is On/Off per device and connection, default Off. A complete 127-path synthetic tool block becomes 1,679 bytes from 3,108 and restores every line, duplicate, and order. It is structural encoding, not a prose summary. Small, unknown, or ineligible results pass through. See compaction-example.json for both full forms.

Setup: What happens during an outage or expired session?
An unavailable gateway or rejected identity does not grant direct-provider access. Check connection status, identity expiry, and the configured route. Do not blindly replay requests with unknown provider outcomes. Recovery and availability depend on your deployment.

Policy: Is policy setup a blank JSON file?
No. Standard, Strict, and Lockdown templates create validated starting documents from configured client/model allowlists. Standard redacts secrets and caps output at 16,000; Strict denies secrets and caps output at 4,000. Lockdown denies all requests. Add budgets and team overlays explicitly.
https://usehormuz.github.io/demo/#policy

Policy: What knobs can an administrator actually turn?
Model and client allowlists, configured fallback routes, maximum output tokens, organization/team/person token or USD caps, configured secret redaction or denial, and supported OpenAI storage/background controls. Policies live in validated configuration or the managed policy CLI; this website is a teaching editor.
https://usehormuz.github.io/demo/#policy

Policy: Can a team override the company’s rules?
Lower scopes only tighten ancestor controls. An Engineering team policy cannot grant a model or client forbidden by the organization, and a person cannot enlarge an ancestor budget. Every applicable cap participates in request admission.
https://usehormuz.github.io/demo/#policy

Policy: How do I check a policy before applying it?
Create and validate a policy file locally, then compare and preview using the administrative commands. Validation changes no active policy. Preview uses current monthly usage without reserving budget. Concurrent requests and reservations can still change whether a later live request is allowed.
https://usehormuz.github.io/demo/#policy

Policy: Can I undo a change? What about requests already running?
Managed policies have immutable versions. Guarded apply can reject a concurrent active-version change. Rollback creates a new activation and preserves history. New requests use the active policy; an in-flight request keeps its original snapshot.
https://usehormuz.github.io/demo/#policy

Policy: What happens when two requests use the last budget at once?
Atomic reservations check all applicable scopes before provider egress. In the example, $0.50 available cannot fund a $0.70 reservation: it is denied with zero provider calls and $0.50 still available. Admission is conservative; a short eventual answer does not guarantee admission.
https://usehormuz.github.io/demo/#policy

Total tokens are input plus output. Cache reads/writes and reasoning may already be subsets of those totals; do not add them again. The example splits uncached and cached input into disjoint categories so its totals reconcile. Categories appear when the provider reports them.

Context: What does context compaction actually remove?
Eligible structure can store repeated prefixes or keys once while preserving exact reconstruction. The 127-path example becomes a 1,679-byte block from 3,108 bytes and restores every line, duplicate, and order. It does not summarize prose or delete selected lines.
https://usehormuz.github.io/demo/#compaction

Context: What can I configure for compaction?
The actual control is On/Off for one saved connection on one device, default Off. There is no aggressiveness slider. Hormuz checks size, exact reconstruction, byte growth, and token counts before selecting a transformation. On means it may try; some results stay unchanged.
https://usehormuz.github.io/demo/#compaction

Context: Which tool results are eligible?
Current automatic mappings are narrow: simple, uncomposed rg --files and rg -n results through Codex exec_command or Claude Code Bash, plus Claude Code Glob path results. Unknown tools, ambiguous history, code, diffs, user/system text, and malformed, oversized, or non-beneficial results pass through.
https://usehormuz.github.io/demo/#compaction

Context: Does my original context get uploaded just to optimize it?
No. Selection, reconstruction checking, and token estimates happen on your device. One selected representation travels to the configured gateway, which can decode it in memory for normal secret checks. Compaction is not encryption and does not prevent the gateway reading governed traffic.
https://usehormuz.github.io/demo/#compaction

Context: Will switching it on save 40% of my bill?
No fixed savings are promised. The release includes bounded synthetic OpenAI evidence, not a forecast for your workload or a provider-invoice result. The website measures one tool block in bytes; token counts, caching, model behavior, and final charges are different measurements.
https://usehormuz.github.io/demo/#compaction

Context: Does the switch require a restart or change an in-flight request?
It applies to the next request; in-flight work retains its starting setting. Review and save a pre-1.2 connector once so its launcher uses the helper. Later toggles need no gateway restart. Start a new chat after toggling for the most stable provider prefix-cache behavior.
https://usehormuz.github.io/demo/#compaction

Compatibility: Does it work with Ollama?
Ollama documents non-stateful OpenAI Responses and Anthropic Messages. Hormuz can configure upstreams for those protocols, but an end-to-end Ollama integration has not been verified. Check streaming, tools, history, token accounting, and policy behavior with your setup before using it.
https://usehormuz.github.io/demo/#setup

Compatibility: Does “OpenAI-compatible” mean every endpoint works?
No. AI Work supports OpenAI Responses, OpenAI-compatible Chat Completions at /v1/chat/completions, and Anthropic Messages; Hormuz also provides its compaction relay and token counting. It does not expose Ollama’s native /api/chat and /api/generate routes. Test your exact client version, model, streaming, and tool behavior before connecting your team.
https://usehormuz.github.io/integrations/#protocols

Compatibility: Can a remote gateway use the Ollama on my laptop?
Localhost means the machine running the gateway. A remote gateway cannot reach your laptop’s server at its own localhost. You must design and secure a reachable route. Token accounting for local inference does not measure GPU, electricity, or hardware cost.
https://usehormuz.github.io/demo/#setup

Compatibility: Does Hormuz govern the coding tool’s shell and MCP traffic?
Hormuz governs supported model requests routed through it. It does not govern every shell command, Git operation, MCP server, browser request, or direct-provider connection. Review those paths separately when defining coverage.
https://usehormuz.github.io/security/#controls
